# เติมไป · Fuel Journal

สมุดเติมน้ำมันและบันทึกการเดินทางส่วนตัว ช่วยดูค่าใช้จ่าย อัตราสิ้นเปลือง และน้ำมันที่ใช้ในแต่ละทริป ออกแบบภาษาไทยสำหรับมือถือและแท็บเล็ต ใช้งานผ่านเว็บหรือติดตั้งไว้บนหน้าจอหลักได้

แอปเป็น static web ไม่มี backend ไม่ต้องสมัครสมาชิก ข้อมูลเก็บบนอุปกรณ์ของผู้ใช้ และรองรับการใช้งานออฟไลน์หลังเตรียมแอปสำเร็จครั้งแรก

## ฟีเจอร์

| เมนู | การใช้งาน |
| --- | --- |
| ภาพรวม | ค่าเติมเดือนนี้ กราฟรายจ่ายย้อนหลัง 6 เดือน อัตราสิ้นเปลือง ต้นทุนต่อกิโลเมตร และรายการเติมล่าสุด |
| คำนวณ | งบเดินทาง อัตราสิ้นเปลือง น้ำมันที่ใช้ตามระยะทาง และระยะทางที่วิ่งได้จากน้ำมันหรืองบ |
| ทริป | บันทึกการเดินทาง ระยะทาง น้ำมัน และค่าใช้จ่าย แยกตามรถ |
| ประวัติ | ดู แก้ไข ลบ และกรองรายการเติมน้ำมันตามช่วงวันที่ |
| รถของฉัน | จัดการรถหลายคัน สำรอง/กู้คืนข้อมูล และดูวิธีติดตั้งแอป |

### บันทึกเติมน้ำมัน

- บันทึกวันที่ เลขไมล์ ยอดจ่าย ชนิดน้ำมัน ปั๊ม และหมายเหตุ
- เลือกกรอกราคาต่อลิตรหรือจำนวนลิตร แล้วคำนวณอีกค่าให้
- ระบุเต็มถังหรือเติมย่อย และแจ้งช่วงที่มีการเติมแต่ไม่ได้บันทึกได้
- แยกประวัติและสถิติของรถยนต์หรือมอเตอร์ไซค์แต่ละคัน

### เครื่องคำนวณ

- **งบเดินทาง:** ระยะทางเที่ยวเดียว/ไป–กลับ ราคาน้ำมัน ค่าใช้จ่ายเพิ่มเติม และหารค่าใช้จ่ายตามจำนวนคน
- เลือกหน่วยอัตราสิ้นเปลืองในงบเดินทางได้ทั้ง **กม./ลิตร** และ **ลิตร/100กม.** พร้อมแปลงค่าเมื่อสลับหน่วย
- ใช้อัตราสิ้นเปลืองจากการกรอกเอง ค่าที่ตั้งไว้ของรถ หรือค่าเฉลี่ยจากประวัติ
- **ความประหยัด:** คำนวณจากระยะทางหรือเลขไมล์ต้น–ปลาย และปริมาณน้ำมันที่ใช้
- **ระยะทาง/น้ำมัน:** ประเมินลิตรที่ใช้ ระยะทางที่วิ่งได้ หรือระยะทางตามงบน้ำมัน

### บันทึกทริป

- ชื่อทริปไม่บังคับ หากเว้นว่างจะแสดงชื่อจากวันที่เริ่มเดินทาง
- กรอกระยะทางรวม หรือใช้เลขไมล์เริ่มต้น–สิ้นสุด
- ติ๊ก **บันทึกเลขไมล์เริ่มต้นไว้ก่อน** เพื่อเก็บทริปที่ยังไม่จบ โดยยังไม่ต้องกรอกเลขไมล์จบหรือข้อมูลน้ำมัน
- กลับมากด **กรอกเลขไมล์จบทริป** แล้วเลือก **จบทริปและกรอกเลขไมล์** เพื่อบันทึกระยะทางเมื่อเดินทางเสร็จ
- เลือกประเมินน้ำมันจากอัตราสิ้นเปลือง หรือกรอกปริมาณที่ทราบว่าใช้จริง
- บันทึกราคาน้ำมัน ค่าใช้จ่ายเพิ่มเติม และหมายเหตุได้
- อัตราสิ้นเปลืองที่ใช้ในทริปถูกเก็บไว้กับทริปนั้น สถิติรถที่เปลี่ยนภายหลังไม่เปลี่ยนผลของทริปเก่า
- ทริปที่ยังไม่จบไม่ถูกรวมในระยะทางและปริมาณน้ำมันสรุป หากยังไม่มีข้อมูลน้ำมัน จะแสดงว่ายังไม่ทราบแทนการเดาค่า

ค่าใช้จ่ายทริปเป็นข้อมูลแยกจากรายการเติมน้ำมัน จึงไม่บวกซ้ำกับรายจ่ายรายเดือน

## เริ่มใช้งาน

1. เข้า **รถของฉัน** แล้วเพิ่มรถคันแรก
2. บันทึกการเติมน้ำมัน หรือเข้า **ทริป** เพื่อเริ่มบันทึกการเดินทาง
3. ใช้เมนู **คำนวณ** วางแผนงบก่อนออกเดินทางได้ แม้ยังไม่มีประวัติเติม
4. ส่งออกไฟล์สำรองเป็นระยะจากหน้า **รถของฉัน**

## หลักการคำนวณ

อัตราสิ้นเปลืองจากประวัติใช้รอบ **เต็มถัง → เต็มถัง** โดยรวมการเติมย่อยที่อยู่ระหว่างรอบ

```text
ระยะทาง = เลขไมล์เต็มถังครั้งหลัง − เลขไมล์เต็มถังครั้งก่อน
ลิตรที่ใช้ = ผลรวมลิตรหลังครั้งก่อนจนถึงครั้งหลัง รวมครั้งหลัง แต่ไม่รวมครั้งก่อน
กม./ลิตร = ระยะทาง ÷ ลิตรที่ใช้
ลิตร/100กม. = 100 ÷ กม./ลิตร
```

ตัวอย่าง: เริ่มเต็มถังที่ 10,000 กม. เติมย่อย 10 ลิตร แล้วเติมเต็มถังอีกครั้งที่ 10,400 กม. จำนวน 20 ลิตร อัตราสิ้นเปลืองเท่ากับ `400 ÷ 30 ≈ 13.33 กม./ลิตร`

- ค่าเฉลี่ยหลายรอบใช้ผลรวมระยะทางหารผลรวมลิตร ไม่เฉลี่ยค่า กม./ลิตร ของแต่ละรอบตรง ๆ
- ช่วงที่ยังไม่ปิดรอบ เต็มถังที่ระยะทางเป็นศูนย์ หรือช่วงที่แจ้งว่าขาดบันทึก จะไม่ใช้สรุปอัตราสิ้นเปลือง
- รายจ่ายรายเดือนนับยอดจ่ายจริงทุกครั้งตามวันที่เติม ไม่จำกัดเฉพาะรอบเต็มถัง
- ต้นทุนต่อกิโลเมตรใช้ยอดจ่ายของรอบที่สมบูรณ์หารระยะทางของรอบเดียวกัน
- ผลน้ำมันและงบเดินทางที่ประเมินเป็นค่าประมาณ ไม่ใช่การวัดน้ำมันคงเหลือในถัง การจราจร น้ำหนักบรรทุก และวิธีขับมีผลต่อการใช้จริง

## ข้อมูลเก็บที่ไหน

ข้อมูลรถ ประวัติเติม ทริป และการตั้งค่าเก็บใน **IndexedDB ของเบราว์เซอร์** ชื่อฐานข้อมูล `fuel` ไม่ได้เก็บลงโฟลเดอร์โปรเจกต์ และไม่มีระบบส่งข้อมูลบันทึกไปเก็บบนเซิร์ฟเวอร์ของแอป

- ปิดเว็บแล้วเปิดใหม่ในเบราว์เซอร์และที่อยู่เดิม ข้อมูลยังเรียกกลับมาได้ ตราบใดที่พื้นที่จัดเก็บนั้นยังอยู่
- ไม่มีบัญชีผู้ใช้หรือการซิงก์ข้ามเครื่องอัตโนมัติ
- แต่ละอุปกรณ์ เบราว์เซอร์ และ origin (protocol + host + port) มีพื้นที่ข้อมูลแยกกัน เช่น `localhost:5173` กับเว็บบน Vercel
- การล้างข้อมูลเว็บไซต์ โหมดไม่ระบุตัวตน หรือการลบพื้นที่จัดเก็บโดยเบราว์เซอร์ อาจทำให้ข้อมูลหาย
- ติดตั้งแอปลงหน้าจอหลักไม่ได้หมายความว่าข้อมูลถูกสำรองขึ้น cloud แล้ว

### สำรองและย้ายข้อมูล

ไปที่ **รถของฉัน → ส่งออกไฟล์สำรอง** เพื่อดาวน์โหลด JSON ซึ่งมีรถ ประวัติเติม ทริป และการตั้งค่า

บนเครื่องปลายทางเลือก **นำเข้าไฟล์สำรอง** แอปตรวจสอบข้อมูลก่อนนำเข้า และขอให้ยืนยันการ **แทนที่ข้อมูลทั้งหมด** พร้อมเริ่มดาวน์โหลดสำรองข้อมูลเดิมให้ก่อน ไม่ใช่การรวมสองชุดข้อมูลเข้าด้วยกัน ควรตรวจว่าไฟล์สำรองดาวน์โหลดสำเร็จก่อนดำเนินการต่อ

ไฟล์สำรองจำกัดขนาด 5 MB และอาจมีชื่อรถ สถานที่ หรือหมายเหตุส่วนตัว ควรเก็บไว้ในที่ที่เหมาะสม

## ออฟไลน์และการติดตั้ง

1. เปิด production build ผ่าน HTTPS หรือ `localhost` ขณะออนไลน์
2. รอให้แสดง **พร้อมใช้ออฟไลน์** ก่อนเปิดใช้โดยไม่มีอินเทอร์เน็ต
3. เพิ่มลงหน้าจอหลักเพื่อเปิดใช้สะดวกขึ้น

| อุปกรณ์ | วิธีติดตั้ง |
| --- | --- |
| iPhone / iPad | เปิดด้วย Safari → เมนูแชร์ → เพิ่มไปยังหน้าจอโฮม |
| Android | เปิดด้วย Chrome → เมนู → ติดตั้งแอป หรือ เพิ่มลงในหน้าจอหลัก |

ตัวเลือกติดตั้งอาจแตกต่างตามเบราว์เซอร์ เมื่อมีรุ่นใหม่ แอปจะแสดงปุ่ม **อัปเดตตอนนี้** ให้บันทึกหรือปิดฟอร์มที่เปิดอยู่ก่อนอัปเดต

Service worker เปิดใช้ใน production build เท่านั้น การรัน `npm run dev` ใช้พัฒนาและไม่ใช่โหมดทดสอบออฟไลน์

## รันในเครื่อง

ต้องมี Node.js ตาม `engines` ใน `package.json` (ขั้นต่ำ 22.12.0) แนะนำ Node.js 24 ให้ตรงกับ workflow และใช้ npm

รันคำสั่งจากโฟลเดอร์โปรเจกต์:

```bash
npm ci
npm run dev
```

เปิด URL ที่ Vite แสดงใน terminal หาก PowerShell บน Windows ไม่อนุญาตให้เรียก `npm.ps1` ให้ใช้ `npm.cmd` แทน `npm`

### เปิดทดสอบบนโทรศัพท์

คอมพิวเตอร์และโทรศัพท์ต้องอยู่ในเครือข่ายเดียวกัน จากนั้นเปิด Network URL ที่ Vite แสดง เช่น `http://<IP-ของคอม>:5173` และอนุญาต firewall หากจำเป็น

การเปิดผ่าน HTTP ด้วย IP ในเครือข่ายเหมาะกับการตรวจหน้าจอ ส่วนการติดตั้ง PWA และ service worker บนโทรศัพท์ให้ทดสอบผ่าน HTTPS ของเว็บที่ deploy แล้ว

### สร้าง production build

```bash
npm run build
npm run preview
```

ไฟล์พร้อมเผยแพร่อยู่ใน `dist/` ส่วน `preview` ใช้ตรวจ build ในเครื่อง ไม่ใช่ production server

## Deploy

### Vercel

โปรเจกต์มี `vercel.json` กำหนด Vite, build command และ output directory ไว้แล้ว

1. นำโค้ดขึ้น GitHub repository ของคุณ
2. ใน Vercel สร้างโปรเจกต์และ import repository นั้น
3. ตั้ง Root Directory ให้ตรงโฟลเดอร์ที่มี `package.json`
4. ตรวจค่าต่อไปนี้ แล้วกด Deploy

| การตั้งค่า | ค่า |
| --- | --- |
| Framework | Vite |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Base path | `/` ซึ่งเป็นค่าเริ่มต้น ไม่ต้องตั้ง environment variable |

แอปไม่มี backend จึงไม่ต้องมี API key หรือฐานข้อมูลภายนอก เมนูใช้ hash navigation เช่น `/#trips` จึงไม่ต้องเพิ่ม rewrite สำหรับแต่ละหน้า

### GitHub Pages

มี workflow ที่ `.github/workflows/deploy.yml` สำหรับ build และ deploy จาก branch `main`

1. นำโค้ดและ `package-lock.json` ขึ้น repository บน GitHub
2. ไปที่ **Settings → Pages → Build and deployment → Source** แล้วเลือก **GitHub Actions**
3. Push เข้า `main` หรือเรียก workflow **Deploy to GitHub Pages** จากแท็บ Actions
4. เมื่อ workflow สำเร็จ เปิด URL ของ Pages ที่แสดงใน deployment

Workflow ใช้ Node.js 24 ติดตั้งด้วย `npm ci` ตรวจ TypeScript รัน unit tests แล้ว build ก่อน deploy โดยนำ base path จากขั้น configure-pages มาส่งให้ `VITE_BASE_PATH` อัตโนมัติ

หาก branch หลักไม่ได้ชื่อ `main` ให้แก้ค่า `on.push.branches` ใน workflow ให้ตรงกับ repository

### กำหนด base path เอง

หากนำไฟล์ไปวางใต้ path เช่น `/fuel/` ให้กำหนด environment variable ตอน build:

```bash
VITE_BASE_PATH=/fuel/ npm run build
```

สำหรับ Windows PowerShell:

```powershell
$env:VITE_BASE_PATH = '/fuel/'
npm.cmd run build
Remove-Item Env:VITE_BASE_PATH
```

Vite assets, manifest และ service worker ใช้ base path เดียวกัน อย่าลืมส่งออกข้อมูลจากเว็บเดิมก่อนย้ายโดเมน เพราะข้อมูลในเครื่องไม่ได้ย้ายตาม deployment

## ทดสอบ

```bash
# ตรวจ TypeScript
npm run typecheck

# Unit tests สำหรับสูตร การตรวจข้อมูล และไฟล์สำรอง
npm test

# ติดตั้ง browser ที่ชุดทดสอบใช้
npx playwright install chromium webkit

# สร้าง production build ก่อนรัน browser tests
npm run build
npm run test:e2e
```

`test:e2e` สร้าง build สำหรับ `/fuel/` เพิ่ม แล้วทดสอบการบันทึก การเปลี่ยนหน่วย ทริปที่ยังไม่จบ การสำรอง/กู้คืน ข้อมูลเดิม การทำงานหลายแท็บ ออฟไลน์ การอัปเดตแอป และ layout มือถือ ชุดตรวจช่องวันที่รันทั้ง Chromium และ WebKit จำลอง iPhone ซึ่งไม่ทดแทนการตรวจบนอุปกรณ์จริง

ค่าเริ่มต้นของ browser tests ใช้พอร์ต 4173 และเริ่ม preview ให้อัตโนมัติ ใน Windows ใช้ได้ตาม config ปัจจุบัน หากรัน browser tests บนระบบอื่น ให้เปิด preview เองแล้วกำหนด `TEST_BASE_URL` เนื่องจากคำสั่ง webServer ใน `playwright.config.ts` ใช้ `npm.cmd`
